# RAG 系统设计指南

## 1. 整体架构

RAG 系统由索引管线和查询管线两部分组成。
索引管线负责把文档处理后存入向量库，查询管线负责根据用户问题检索并生成回答。
两条管线解耦，可以独立优化。

### 1.1 索引管线

索引管线包括文档加载、分块、向量化、入库四个步骤。
每一步都有优化空间。文档加载阶段需要支持多种格式，包括 PDF、Word、Markdown、TXT 等。
分块阶段需要根据文档结构选择合适的策略，比如 Markdown 按标题切，PDF 按页切。
向量化阶段选择合适的 Embedding 模型，中文场景推荐 BGE 系列。
入库阶段需要保证幂等性，避免重复索引。

### 1.2 查询管线

查询管线包括问题改写、检索、重排序、生成四个步骤。
问题改写用于多轮对话中指代消解。
检索采用向量 + BM25 混合策略，通过 RRF 融合。
重排序使用 Cross-Encoder 对候选精细打分。
生成阶段通过 Prompt 约束模型只基于检索内容作答。

## 2. 关键技术选型

### 2.1 Embedding 模型

常用模型包括 BGE 系列、M3E、OpenAI text-embedding-3。
中文场景推荐 BGE，bge-small-zh-v1.5 用于开发，bge-large-zh-v1.5 用于生产。

### 2.2 向量数据库

Chroma 适合开发和中小规模，零运维。
Milvus 适合生产级大规模，支持十亿级向量。
Qdrant 兼顾性能与易用性，Rust 实现。
FAISS 是库而非数据库，需要自己封装持久化。

### 2.3 大语言模型

可以选择 DeepSeek、Qwen、GPT-4 等。
OpenAI 兼容协议让切换变得容易，只需改 base_url 和 model 名。

## 3. 评估与优化

RAGAS 是常用的评估框架，提供四个核心指标：
Faithfulness 衡量答案是否基于检索内容。
Answer Relevancy 衡量答案是否切题。
Context Precision 衡量检索到的相关内容占比。
Context Recall 衡量是否召回了回答所需的全部信息。

优化方向包括：
混合检索，向量 + BM25 融合提升召回。
重排序，Cross-Encoder 精排提升准确率。
查询改写，HyDE 和多轮改写解决语义鸿沟。
